# ADR-003: Scope Pivot from AI Plagiarism Detection to Admin Dashboard & School Management Subsystem

**Date:** 2026-11-04  
**Status:** accepted

## Context

In the initial semester roadmap, Sprint 2 included an external AI submission/plagiarism detection integration for student essays alongside an outbound third-party email/SMS `NotificationService`. However, during midterm evaluation and architectural review of our K-8 School Information System (SIS), three practical and architectural issues surfaced:

1. **Missing Institutional Administration Tier:** While the system supported Student, Teacher, and Parent views, there was no in-app mechanism for school administrators to monitor campus-wide KPIs, provision new user accounts (`student`, `teacher`, `parent`, `admin`), link parents to children (`public.students.parent_id`), schedule class sections with room numbers and meeting times, or manage student class enrollments (`public.enrollments`).
2. **External API Fragility & Cost:** Relying on paid third-party AI detection APIs and external SMTP/SMS gateways introduced external API key dependencies that would break offline local grading and CI runs for peer reviewers.
3. **Domain Rule Richness:** A core goal of CEN 5064 is encapsulating rich, unit-tested business logic inside the Domain tier without mocks. An institutional Admin Dashboard introduces deterministic, high-value domain rules (school-wide attendance health classification, student-to-teacher ratio calculation with zero-division guards, room format validation, teacher role verification, duplicate enrollment prevention, parent-child link validation, and cryptographically secure role-based school ID generation).

## Decision

1. **Replace AI Plagiarism Detection with the Admin Dashboard & School Management Subsystem:** Formally pivot scope to build the full `backend/admin/` package (`models.go`, `handlers.go`, `admin_test.go`) and `frontend/components/dashboards/AdminDashboard.tsx` (`AdminDashboard.test.tsx`).
2. **Encapsulate Admin Business Rules in the Domain Tier:** Implement pure domain models and methods in `backend/admin/models.go` (`SchoolMetrics.EvaluateAttendanceStatus()`, `CalculateSchoolMetrics()`, `AdminClassSection.Validate()`, `ValidateStudentEnrollment()`, `AdminUserRecord.MatchesFilter()`, `FilterUsers()`, `CreateUserRequest.Validate()`, `ValidateParentStudentLink()`, `GenerateSchoolUserID()`, and `HashUserPassword()`).
3. **Keep External Notification Service Out-of-Scope (`<<planned>>`):** Fulfill classroom communication via in-app Class Announcements (`public.class_announcements`) and the unified Academic Calendar (`frontend/app/calendar/page.tsx`), while explicitly marking external email/SMS (`NotificationService`) as `<<planned>>` with dashed borders in UML diagrams.

## Consequences

- **Positives:**
  - **Complete 4-Role SIS:** All four user roles (`student`, `teacher`, `parent`, `admin`) now have complete, end-to-end connected workflows backed by Supabase PostgreSQL persistence.
  - **Self-Contained Provisioning:** Administrators and peer reviewers can create users, attach parents/children and student medical info (`allergies`, `emergency_contact`, `notes`), schedule classes, and enroll students directly from the UI without running manual SQL inserts.
  - **100% Offline Domain Testability:** Every admin business rule is verified by fast, deterministic Go unit tests (`backend/admin/admin_test.go`) and Vitest component tests (`AdminDashboard.test.tsx`) with zero external third-party API keys required.
- **Trade-offs:**
  - Free-form essay and file-based submissions are flagged by `GradeAssignment()` and `EvaluateSubmissionFeedback()` as `"Needs Manual Grading"` for teacher review (`PUT /api/submissions/:id/grade` with `teacher_feedback`) rather than being scored by an external AI detector.
