# ADR-001: Architecture and Tech Stack Selection for K-8 School Information System

**Date:** 2026-09-07  
**Status:** accepted

## Context

Building a School Information System (SIS) for K-8 students, teachers, parents, and administrators requires clear separation of concerns across tiers, support for role-based dashboards, and reliable data persistence for grades, attendance, and assignments. The system must satisfy course architectural requirements for strict tier boundaries (Presentation, Service, Domain, Data) while delivering reliable testing and straightforward deployment within semester deadlines.

## Decision

Adopt a decoupled 4-tier client-server architecture:
1. **Presentation Tier:** Next.js (React 19) with Tailwind CSS and Shadcn UI for component composition, client-side routing, and role-guarded pages.
2. **Service & Domain Tier:** Go with Fiber (v3) providing a high-performance REST API. Domain logic (such as assignment grading and prerequisite validation) is written as pure, testable functions decoupled from HTTP frameworks.
3. **Data Tier:** PostgreSQL (hosted on Supabase) accessed using `pgxpool` connection pooling for relational data storage, schema enforcement, and ACID transactions.

## Consequences

- **Positives:** Clean separation of concerns allows the frontend and backend to evolve independently. Domain business rules can be verified with rapid unit tests without database or network mocks. PostgreSQL ensures strong consistency for grades, enrollments, and user records.
- **Trade-offs:** Requires coordinating two development environments (Node.js and Go) and maintaining typed contracts across the network boundary.
